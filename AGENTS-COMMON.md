ОБЩЕЕ ДЛЯ ВСЕХ АГЕНТОВ (Liquid)
- Проект: Electron-браузер Liquid, репозиторий tekeyaa/Liquid-pc (git remote origin). База: коммит 23bcff4 (ветка v1.24 = выпуск 1.36.0-beta). Ты в отдельном git worktree — работай только в нём.
- Цель пользователя: браузер быстрее и ест меньше оперативной памяти (ориентир — сам браузер ~300 МБ), всё стабильно, видео ровно 60 кадров. Стабильность важнее выигрыша: лучше меньше, но без поломок.
- ОБЯЗАТЕЛЬНОЕ правило пользователя: любое автоматическое ограничение, пауза, авто-отключение или авто-переключение — НЕ молча: пользователь должен это видеть (всплывающее сообщение/пометка в интерфейсе + строка в журнале). Иначе он думает, что браузер «глючит».
- Язык: комментарии в коде, сообщения коммитов, тексты интерфейса — по-русски, в стиле существующего кода (короткие строки-комментарии «почему», без англицизмов в интерфейсе).
- Тесты: tests/liquid.spec.js (Playwright + Electron, Windows), tests/perf.spec.js (замеры против Chromium), tests/rtx2-gl.js. Локально Electron не установлен (в контейнере нет GPU и скачивание бинарников Electron может быть недоступно) — проверяй через CI: push своей ветки запускает workflow «Автотесты» (.github/workflows/tests.yml) на windows-latest. Смотреть: gh run list -R tekeyaa/Liquid-pc -b <ветка>, gh run watch <id> -R tekeyaa/Liquid-pc --exit-status, gh run view <id> --log. Синтаксис JS проверяй node --check.
- Git: коммить в СВОЮ ветку (имя дано в задаче) и пушь её: git push origin HEAD:<ветка>. НИКОГДА не пушь в v1.24 и main, не меняй version в package.json и CHANGELOG.md — выпуском занимается руководитель. Сообщение коммита заканчивай строками:
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_012xGgCi1JHyt4xdyzRJ4sD1
- Параллельно с тобой другие агенты меняют main.js и renderer/: делай изменения точечными, не переформатируй чужой код, не переименовывай без нужды — так слияние будет простым.
- Итоговый отчёт (последнее сообщение) — по-русски, коротко: что сделал, ЦИФРЫ до/после (из CI), ветка и коммит, статус CI, риски/что не доделано, и черновик записи для CHANGELOG (3–8 пунктов, простым языком для пользователя, в стиле существующих записей в CHANGELOG.md).

ПРОДОЛЖЕНИЕ ПОСЛЕ ОБРЫВА (лимит, остановка агента) — ОБЯЗАТЕЛЬНО:
- Работа должна переживать внезапную остановку. Коммить и пушь свою ветку после КАЖДОГО осмысленного шага (минимум раз в ~20–30 минут работы), даже если это незаконченная работа: префикс сообщения «WIP:».
- Веди файл .progress/<твоя-ветка>.md в своей ветке (коммить вместе с кодом): цель, что уже сделано (с коммитами), что сейчас в работе, следующий шаг, цифры замеров с номерами прогонов CI, найденные причины и гипотезы. Пиши так, чтобы новый агент мог продолжить с середины, прочитав только этот файл. Руководитель удалит .progress/ при слиянии.
- Если ветка уже существует на origin при старте — это продолжение: сделай git fetch origin <ветка> && git checkout -B <ветка> origin/<ветка>, прочитай .progress/<ветка>.md и продолжай с указанного шага, не начиная заново.
