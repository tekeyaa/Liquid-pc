# load-fast — ход работы

## Цель
1. Убрать лишние ~100 мс загрузки страницы (perf: «обычный» против «Chromium (эталон)» в одном прогоне).
2. Заготовленная новая вкладка (spareWv в renderer/app.js) держит ~100 МБ в пустом браузере — сделать умнее,
   новая вкладка не медленнее ~60 мс. Автовыгрузка — со строкой в журнале (правило пользователя: не молча).
База: origin/v1.24 = 7196777 (1.37.0-beta). Блокировщик (main/adblock*.js) не трогать — им занят другой агент.

## Цифры базы (CI 42930174330, v1.24, сравнивать только внутри одного прогона)
- обычный 437 / 446 мс; без блокировщика 426; без перехватов (нет onBeforeSendHeaders и блокировщика) 385;
  голый webview (ещё и без preload) 373; Chromium 298 (его загрузки падают 882→233 — разогрев, шумно).
- новая вкладка: с заготовкой 44/47, без 107/104.
- память пустой браузер: totalWs 786 МБ, из них about:blank-заготовка ~101 МБ ws (priv ~28).

## Гипотезы
- Главное: hardenSession() в main.js в режиме «Chrome» (по умолчанию) вешает onBeforeSendHeaders на ВСЕ запросы
  (подмена Sec-CH-UA) — каждый запрос (330 на heavy.html) ждёт основной процесс. ≈40–50 мс.
- Окно: saveSession и история уже отложены (400/800 мс). Полоска загрузки + кружок — бесконечные анимации,
  без видеокарты CI рисует их процессором.
